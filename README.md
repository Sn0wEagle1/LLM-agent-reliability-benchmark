# Стенд оценки надёжности LLM-агентов

Материалы к статье «Исследование методов повышения надёжности интеллектуальных агентов на основе больших языковых моделей при взаимодействии с информационными системами».

Стенд моделирует службу технической поддержки: агент читает и изменяет заявки через инструменты. Сравниваются контроль данных, детерминированные функции, ограничение инструментов, верификация, контроль выполнения и подтверждение операций. Внешние информационные системы не подключаются.

## С чего начать

Для первого знакомства достаточно трёх файлов: [карта проекта](docs/architecture.md) объясняет связи модулей, [протокол](docs/protocol.md) — условия эксперимента и расчёт показателей, [таблица результатов](analysis/tables.csv) — полученные значения. В [описании инструментов](docs/tools.md) перечислены операции, доступные агенту.

## Состав

- `src/` — агент, имитационная система, инструменты, задачи и конфигурации.
- `experiments.py` — состав серий и начальные значения генератора.
- `run.py` — запуск и возобновление серий.
- `prompts/` — системные инструкции, запросы задач и примеры собранных сообщений.
- `docs/` — протокол, описания инструментов и схемы параметров.
- `results/` — журналы запусков, использованные в статье.
- `metadata/experiment.json` — модель, параметры генерации и сведения о коррекции эталона.
- `analyze.py` — расчёт показателей из журналов; результаты в `analysis/`.
- `tests/` — проверки эталонов, выгрузки промптов и воспроизведения расчётов.

## Проверка без модели

Требуется Python 3.12 или новее. Внешних Python-зависимостей нет.

Команды ниже выполняются из корня проекта. Из другой рабочей папки можно передать абсолютный путь к `run.py` или `analyze.py`: файлы данных находятся относительно скриптов. Для использования классов в своём коде при доступном корне проекта применяются пакетные импорты:

```python
from src.agent import Agent
from src.tools import check_value, to_ollama, ALL_SPECS
```

`src` — Python-пакет; его модули используют относительные импорты. Добавлять сам каталог `src` в `PYTHONPATH` не требуется. Точки запуска приложения — корневые скрипты, например `python run.py`, а не `python src/agent.py`.

```console
python -B -m unittest discover -s tests -v
python -B analyze.py
python -B run.py --series main --plan
```

`analysis/tables.csv` содержит показатели по конфигурациям, `analysis/summary.json` — также парные сравнения и результаты пяти повторов базовой конфигурации. Эти команды не обращаются к LLM.

## Новые запуски

Нужны локальный Ollama и загруженная модель Qwen3-14B соответствующего квантования. Сервер должен быть доступен по адресу `http://localhost:11434`. Веса модели не включены в архив. Тег модели необходимо сопоставить с квантованием; команда проверяет Q4_K_M или Q8_0 и сохраняет digest.

```console
python -B run.py --series main --model qwen3:14b
python -B run.py --series holdout --model qwen3:14b
python -B run.py --series general_df --model qwen3:14b
python -B run.py --series extra_seed --model qwen3:14b
python -B run.py --series ablation --model qwen3:14b
python -B run.py --series q8 --model qwen3:14b-q8_0
```

Для короткой проверки:

```console
python -B run.py --series main --tasks T4,T12 --configs base,combined2 --out smoke_runs
```

Повтор той же команды продолжает незавершённую серию. При изменении модели, исходников или состава запусков нужен другой каталог `--out`. Файл `.running` предотвращает одновременную запись; после аварийного завершения его можно удалить, предварительно проверив, что процесс остановлен. Незавершённая строка JSONL требует восстановления файла из резервной копии либо удаления только этой строки.

Новые результаты записываются в `runs/<серия>/`, опубликованные журналы не перезаписываются. Для повторного анализа новых полных серий скопируйте их `results.jsonl` в отдельный каталог под именами `main.jsonl`, `holdout.jsonl` и т. д. и передайте этот каталог через `analyze.py --results <каталог>`.

## Промпты и воспроизводимость

Промпты и описания инструментов сохранены в формулировках эксперимента. Их можно повторно выгрузить командой `python -B export_materials.py`. Системная дата `29.09.2026` является частью исходного запроса; менять её при воспроизведении не следует. Динамические сообщения обратной связи строятся в `src/agent.py`; пример начального запроса доступен в `prompts/initial_request_example.json`.

В тестовых заявках встречаются названия прикладных программ, в том числе 1С. Это исходные синтетические обращения пользователей, а не подключение к этим программам.

Механизмы, промпты и критерии задач сохранены из экспериментального снимка. При подготовке убраны декоративные комментарии, импорты оформлены через пакет `src`, общий тип задачи вынесен в `task_types.py`. Код запуска и выгрузки материалов оформлен отдельно. Наличие кода не гарантирует побитового совпадения новой генерации: существенны версия Ollama, модель и аппаратная среда.

Для исходной основной, абляционной и Q8-серий журнал содержит тег модели, но не digest. Digest дополнительной Q4-серии сохранён в `metadata/experiment.json`. Это ограничение исходных данных, а не пропущенный файл публикации.

Порядок измерения, определение ошибок и исправление H05 описаны в [протоколе](docs/protocol.md). На исходных задачах методы дорабатывались; отложенная серия использовалась без настройки механизмов. Подтверждение пользователя имитируется эталонными правилами.
